基本设置

按番号从迅雷字幕 API 下载外挂字幕，写入视频同目录的 <片名>.chi.srt 或 <片名>.chi.ass。 只处理所选影视库里完全没有字幕的影片，115 同步下来的 <片名>.srt 永远不会被覆盖。

在「右键 → 修改字幕 → 搜索字幕」里，每条结果后面会有 预览和下载两个按钮：预览会把整份字幕读出来看， 只占用服务器内存，不会写进影片文件夹。

关闭后两个计划任务都不再下载任何字幕。

下载与筛选
只有简体中文和繁体中文的候选会进入对比，英文、日文等直接丢弃。 选中的这一种优先；没有合适的时才用另一种。
每次运行最多处理多少部影片。
每部影片最多下载多少条候选来比较体积。
两次搜索之间的等待时间，避免请求过快。
同时下载多少条候选，1~8，默认 4。
到点就用手上已下载的候选排序，不再等慢 CDN。
日志写入 Jellyfin 服务器日志，时间戳为北京时间。
勾选后，已经存在 .chi.* 字幕的影片也会重新比较并升级。 115 同步的字幕不受影响。
AI 评审（可选）

按台词字符数排出的前几名，再让大模型横向比较一次：机翻往往更长 （每个语气词都被逐字翻出来），但读起来驴唇不对马嘴。开启后 AI 只负责在候选之间排序， 连接失败或返回异常时自动回退到字符数排序，不影响字幕下载。

每部影片会调用一次模型（前 N 名放在同一个请求里比较）。
Open Code 已内置 https://opencode.ai/inference/go/openai/v1， 并自动附带它要求的 x-opencode-session 请求头。
仅「自定义」需要填：任何 OpenAI 兼容网关，会自动补上 /chat/completions。
Open Code 可用：deepseek-v4.1-flash、glm-5.3-flash、kimi-k3 等。
保存在服务器插件配置里，不会写进日志。
候选先按条数分档（相差 2% 以内算同一档，例如 500 条和 504 条）， 取条数最多的前 3 档，每档再挑几份送进同一个请求。默认 2，即最多 6 份。 条数最多的那批常常是同一份机翻的不同转码，只取前 N 名会把人翻挤掉。
预览缓存

预览过的字幕全文只在服务器内存里留一份，30 分钟没用就过期，最多同时保留 24 份， 重启即清空，任何时候都不会落盘。
