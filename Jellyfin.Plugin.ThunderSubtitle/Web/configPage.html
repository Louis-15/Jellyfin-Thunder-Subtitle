基本设置

从迅雷字幕 API 下载外挂字幕，写入视频同目录的 <片名>.chi.srt 或 <片名>.chi.ass。

在「右键 → 修改字幕 → 搜索字幕」里，每条结果后面会有 预览和下载两个按钮：预览会把整份字幕读出来看， 只占用服务器内存，不会写进影片文件夹。

关闭后两个计划任务都不再下载任何字幕。
目标影视库
正在加载影视库…

勾选需要本插件处理的影视库，再为每个库分别设置下面三项（未勾选的库只显示设置，不会被处理）：

  • 检索方式：番号库（如 ABF-363）选「番号搜索」； 普通影视库选「片名搜索」，按片名 + 年份 / 季集查。
  • 自动补全：只处理完全没有字幕的影片。 已有网盘同步的 <片名>.srt、内嵌字幕或本插件写的 .chi.* 都会跳过，永远不会被覆盖。 选「否」时该库只有手动「搜索字幕」才会查。
  • 自动择优：只处理已有本插件写的 .chi.* 的影片，重新搜索一遍，遇到更完整或非机翻的候选才替换； 网盘同步的 .srt 和内嵌字幕同样不会被碰。 自动补全选「否」时该项隐藏。
字幕下载与筛选

语言偏好按影片类型自动决定，不需要手动选： 非中文影视优先「简英双语」，其次纯简体，最后繁体； 中文影视优先纯简体，其次纯繁体；日本AV 优先纯简体，其次纯繁体。 英文、日文等非中文候选一律丢弃。

默认不碰：内嵌字幕通常已经能看。打开后，即使视频本身带内嵌字幕， 自动补全也会下载一份外挂中文字幕 —— 适合内嵌的是 PGS 图形字幕、 想换成能搜索能调样式的那种，或者单纯觉得内嵌那份不够好的情况。 手动搜索不受此开关影响。

处理范围与下载

每次运行最多处理多少部影片。
每部影片最多下载多少条候选来比较。
两次搜索之间的等待时间，避免请求过快。
同时下载多少条候选，1~8，默认 4。
到点就用手上已下载的候选排序，不再等慢 CDN。

候选筛选

下载完先近似去重（同一份机翻被不同站点转码、改名、换标点后 文件哈希完全不同，精确去重拦不住，它们会一起挤进送审名额）， 再淘汰有明显硬伤的候选（含中文率过低、满屏未译标注、 中间大段空白、断句粗到没法用），最后才决定送审名单。

0.95（默认）比较稳：0.99 会漏掉改标点的版本，0.90 会把「同一影片的不同翻译」误合并。 填 1 表示关闭。
每种语言（简体 / 繁体 / 简英双语）最多挑几份送进同一个请求，默认 5，总数不超过 12 份。 首选语言凑不满时，余量会让给其他语言档位，尽量多给模型几份做横向比较。 台词字数不参与排序 —— 双语字幕夹着整行英文，字数天然翻倍， 按字数排会把真正干净的纯中文台本挤出送审名单。

AI 送审

送审的不是孤立单句，而是按时间轴对齐的若干连续片段： 同一时刻的所有候选放在一起，模型才能判断「这句是不是联系上下文翻的」。 片段越多越全面，也越费 token。

超过这个时间就放弃 AI、按本地规则排序。默认 100 秒。
默认 6，覆盖片长的 12%～90%。
非中文影视与日本AV 用这个值，默认 8。
错别字是稀疏事件，抽样要比另外两类更密。默认 10。

质量门槛

简体档最高分低于这个值时，若繁体档分数更高就改用繁体。填 0 关闭降级。 其余类型的影片忽略此项。
非中文影视默认「有简英双语就用双语」。若纯简体 / 繁体版本高出这个分数， 就改用分数更高的那份（只提这一份，不整体提升档位）。默认 8，填 0 关闭。
只写日志提醒，不参与排序，更不会淘汰字幕。

评分缓存

「自动补全」和「自动择优」会搜到同一批候选，没有缓存就会发两次一模一样的请求。 缓存键包含模型名与提示词版本：换模型或改了提示词，旧分数自动失效。

日志写入 Jellyfin 服务器日志，时间戳为北京时间。
AI 接口

只用于把候选字幕的译文放在一起横向比较，挑出读起来最像中文的那份。 字幕文件、视频文件名、媒体库内容都不会被修改。

关闭后「自动补全」只按本地规则排序（健康度、条数偏离度、名称关键词）， 不会调用任何接口。
Open Code 已内置 https://opencode.ai/inference/go/openai/v1， 并自动附带它要求的 x-opencode-session 请求头。
仅「自定义」需要填：任何 OpenAI 兼容网关，会自动补上 /chat/completions。
只保存在服务器插件配置里，不会写进日志。
Open Code 可用：deepseek-v4.1-flash、glm-5.3-flash、kimi-k3 等。
预览缓存

预览过的字幕全文只在服务器内存里留一份，30 分钟没用就过期，最多同时保留 24 份， 重启即清空，任何时候都不会落盘。
